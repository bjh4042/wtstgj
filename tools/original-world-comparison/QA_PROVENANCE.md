# Isolated selected-map T1 original World check

This development-only experiment uses two explicit synthetic QA starts, never an actual user's save. The win source descends from a fresh disposable original game session with the QA player label and an assisted high-level party. The loss source descends from the separately reviewed original-API admitted-loss setup, using original developer encounter/capture convenience and original storage exchange. That setup is not claimed to be natural-world exploration and does not fabricate damage, levels, or a defeat. Original travel and interaction APIs brought both sources through S6 initialization and the native S7/S8 route into GYM8. The browser integration does not edit their positions, levels, HP, flags, rewards, or battle outcomes.

The visible win-QA and loss-QA buttons select these source-provenanced records. They are distinct testing scenarios, not normal new-game balance examples. All subsequent battle actions are genuine original-engine move/switch intentions. A loss uses the original recovery decision and renders its committed native S7 destination; no caller supplies an aftermath or a replacement pose.

This exact T1 profile has its own compiled browser-storage namespace and strict export format. It does not migrate paired-port records or ordinary game saves. Starting fresh QA refuses to overwrite an occupied slot. Cold Load reads only a completed record in this profile. Unfinished battles are not resumed after process loss. This scope activates only T1, not other trainers, shops, facilities or events.

All artwork is reused byte-for-byte from already published original project assets. The exact derived S7 collision gzip text and bounded raw-mask reconstruction are reused unchanged from the selected paired-port check. No new image conversion, artwork upload or visual quality change is involved.

This remains an isolated comparison experiment, not a production architecture switch or a complete game release. Actual tab-focus pause is explicitly unverified in the available browser environment. Reported timings cover automation through visible readiness, not physical display paint or guaranteed performance.
